\begin{abstract}
Federated learning (FL) enables on-device adaptation of large language models (LLMs) without centralizing sensitive data, yet practical deployment on heterogeneous edge devices is challenged by task diversity, resource constraints, and high communication overhead. Naïve task-agnostic aggregation (e.g., FedAvg) and uniform-rank low-rank adaptation (LoRA) may suffer from negative transfer, suboptimal personalization, and inefficient utilization of device budgets.

This paper presents \textbf{ATLAS}, an adaptive task-aware FL framework for parameter-efficient fine-tuning of transformer-based LLMs on heterogeneous clients. The current ATLAS architecture integrates four phases: (i) representation-based task discovery using compact frozen-backbone fingerprints and multi-metric cluster selection, (ii) device- and data-aware heterogeneous LoRA rank allocation under explicit memory budgets, (iii) state-consistent split federated learning with adaptive split selection and dual-path cluster aggregation, and (iv) MIRA-style LoRA-only Laplacian regularization over a block-diagonal task graph together with communication-efficient INT8 LoRA exchange and FP32 server-side computation~\cite{mira,splitfed,llm_int8,qlora,zeroquant,smoothquant}.

We implement ATLAS in an end-to-end pipeline and evaluate it on a heterogeneous GLUE federation with three tasks, nine clients, and three transformer backbones~\cite{glue}. Across DistilBERT, GPT-2, and Qwen-2.5-0.5B, ATLAS improves macro-average accuracy over standard FedAvg by 16.18, 24.83, and 6.86 percentage points, respectively, while reducing LoRA synchronization traffic and eliminating the weak-device failures observed under the baseline.
\end{abstract}

\section{Introduction}

\IEEEPARstart{F}{ederated} learning (FL) enables collaborative model adaptation without centralizing user data, making it attractive for privacy-sensitive on-device personalization. However, federated adaptation of transformer-based large language models (LLMs) on heterogeneous edge devices is constrained by three coupled factors: (i) \emph{task heterogeneity} across clients, (ii) \emph{resource heterogeneity} (memory/compute), and (iii) \emph{communication bottlenecks} that make full-model synchronization impractical.

Task heterogeneity leads to \emph{negative transfer} when a single global model is optimized across diverse NLP tasks, such as sentiment analysis, paraphrase detection, and grammatical acceptability. Classical FL methods such as FedAvg focus on a single global objective, which can degrade both global quality and per-client personalization when client objectives differ substantially~\cite{fedavg}. Federated multi-task learning (FMTL) frameworks instead enforce structured sharing across related clients or tasks, often using graph-based couplings to preserve task-specific specialization while still leveraging common structure~\cite{mira}.

In practice, task discovery itself becomes non-trivial when multiple tasks share the same label cardinality. In such settings, gradient-direction fingerprints can collapse toward a common classifier geometry, even though the underlying input distributions remain distinct. This motivates ATLAS to use representation-space fingerprints derived from a frozen backbone, following the broader intuition behind clustered FL and sentence-level semantic embeddings~\cite{cfl,ifca,sbert}.

At the same time, edge devices exhibit strong variation in memory, compute, and network bandwidth, which makes full-model fine-tuning of LLMs impractical in many realistic deployments. Parameter-efficient fine-tuning (PEFT) methods such as LoRA reduce the number of trainable parameters by injecting low-rank adapters into selected layers, thereby lowering memory and often communication costs when only adapters are exchanged~\cite{lora}. Complementary strategies such as split learning partition the model between clients and a server, offloading deep layers and most of the backpropagation to the server to further reduce client-side load.

However, combining heterogeneous LoRA with split execution introduces two additional systems challenges that are usually hidden in homogeneous FL setups: (i) adapter aggregation must remain well-defined when clients instantiate different ranks, and (ii) sequential access to a shared split server can induce state mismatch between a client's bottom adapter state and the server-side suffix it interacts with. ATLAS addresses both issues through rank-aware aggregation rules and state-consistent split execution inspired by recent split-FL and personalized FL formulations~\cite{hsplitlora,splitfed,scaffold,pfedme,fednova}.

Existing work has explored FMTL (e.g., MIRA~\cite{mira}), heterogeneous PEFT under device constraints (e.g., FAH-QLoRA~\cite{fah_qlora}), and split federated learning (e.g., SplitLoRA/HSplitLoRA/TITANIC~\cite{splitlora,hsplitlora,titanic}), largely in isolation. These approaches do not jointly address representation-based task discovery, heterogeneous-rank aggregation, state-consistent split execution, and graph-based personalization under communication-efficient adapter exchange.

This paper presents \textbf{ATLAS}, an adaptive task-aware FL framework for parameter-efficient fine-tuning of transformer-based LLMs on heterogeneous clients. ATLAS integrates four phases: (i) representation-based task clustering via compact backbone fingerprints, (ii) device- and data-aware heterogeneous LoRA rank allocation under explicit memory budgets, (iii) split federated learning with adaptive split selection, client-specific server-state synchronization, and dual-path aggregation, and (iv) MIRA-style Laplacian regularization over an RBF-kernel task graph derived from those fingerprints.

We implement ATLAS in an end-to-end pipeline and evaluate it on a heterogeneous GLUE federation with three tasks, nine clients, and three backbones. The completed study shows consistent gains over standard FedAvg across all evaluated models, together with lower adapter communication cost and improved robustness for weak devices.

\textbf{Contributions.}
ATLAS makes the following contributions:
\begin{itemize}
\item Representation-based task discovery: ATLAS derives frozen-backbone fingerprints from averaged [CLS]/pooled hidden states and selects clusters with a multi-metric criterion that penalizes fragmentation, improving task separation when gradients are weakly informative or tasks share the same label structure~\cite{sbert,cfl,ifca}. A compact PCA target is retained only as an optional compression fallback for high-dimensional fingerprint variants.
\item Budget-aware heterogeneous LoRA: ATLAS allocates per-layer LoRA ranks from discrete candidates under explicit adapter-memory budgets, augments attention and FFN projections, and caps ranks for low-resource tasks to avoid over-parameterization on small local datasets~\cite{lora,fah_qlora}.
\item Dual-path split federated optimization: ATLAS combines heuristic split selection with state-consistent split execution, LoRA-only pre-aggregation personalization, and weighted cluster-level averaging of shared non-LoRA parameters, enabling heterogeneous-rank collaboration without cross-task contamination~\cite{mira,splitfed,hsplitlora,pfedme}.
\item Communication-aware personalization: ATLAS applies a MIRA-style Laplacian over a block-diagonal task graph and couples it with per-channel INT8 LoRA transmission plus FP32 dequantized computation, reducing adapter traffic while preserving the small inter-client differences required by graph regularization~\cite{llm_int8,qlora,zeroquant,smoothquant}.
\end{itemize}

\section{Related Work}
\label{sec:related}

\subsection{Federated Multi-Task Learning and Personalization}

Classical FL algorithms such as FedAvg optimize a single global objective by averaging client updates across all participants~\cite{fedavg}. When clients solve different but related NLP tasks, na\"{i}ve global averaging can induce negative transfer, where updates from one task harm performance on another, ultimately degrading both global quality and per-client personalization.

Federated multi-task learning (FMTL) aims to mitigate this by introducing structured sharing across tasks rather than uniform mixing. MIRA, for instance, introduces graph-based coupling via Laplacian regularization, encouraging similar tasks to remain close in parameter space while preserving per-task specialization~\cite{mira}. Clustered FL methods such as CFL and IFCA likewise show that constraining collaboration to task-homogeneous groups is critical when client objectives diverge~\cite{cfl,ifca}. However, these methods typically assume either full-model training or clustering signals that remain reliable under homogeneous label semantics.

ATLAS borrows the Laplacian idea but adapts it to (i) LoRA-only personalization, (ii) representation-derived graphs rather than purely gradient-derived ones, and (iii) split execution on constrained devices. The representation view is motivated by sentence-embedding work showing that frozen backbone features often separate tasks before fine-tuning~\cite{sbert}.


\subsection{Parameter-Efficient Fine-Tuning under Device Constraints}

Parameter-efficient fine-tuning (PEFT) techniques such as LoRA reduce fine-tuning cost by injecting low-rank adapters into selected layers while keeping the base model frozen~\cite{lora}. This design significantly lowers the number of trainable parameters and can reduce communication when only adapters are shared, but most existing deployments use \emph{uniform} ranks across layers and devices, which can exceed the capacity of low-end hardware and underutilize high-end devices.

Recent work on federated adaptation of LLMs combines LoRA with quantization and heterogeneous configurations to better match device capabilities. FAH-QLoRA, for example, explores joint design of quantization schemes and LoRA adapters, enabling adaptive configurations across clients with different budgets~\cite{fah_qlora}. Quantization-aware PEFT studies such as LLM.int8(), QLoRA, ZeroQuant, and SmoothQuant further show that low-bit communication or storage is viable provided arithmetic is carried out in sufficiently precise formats~\cite{llm_int8,qlora,zeroquant,smoothquant}. Nonetheless, these approaches typically remain task-agnostic at the federation level: aggregation is still performed globally across all clients, and there is no explicit mechanism to prevent cross-task mixing via clustering or graph-based personalization.

ATLAS is task-aware via representation clustering and graph regularization, atop heterogeneous LoRA and communication-aware adapter exchange.


\subsection{Split Learning and Split-PEFT for LLMs}

Split learning partitions a model into a client-side prefix and a server-side suffix, allowing clients to compute early-layer activations while offloading deeper layers, loss computation, and most of backpropagation to a powerful server. This paradigm is appealing for edge LLMs because it reduces client memory and compute requirements without fully sacrificing privacy.

Basic split-PEFT methods combine model splitting with LoRA-style adapters to further decrease client-side state. SplitLoRA and HSplitLoRA, for instance, integrate split learning with LoRA adapters to reduce client memory by 50--70\% and to enable heterogeneous rank allocation while keeping accuracy close to centralized fine-tuning~\cite{splitlora,hsplitlora}. SplitFed further highlights the need to keep client and server states synchronized when server-side layers are shared across clients~\cite{splitfed}. However, these methods focus primarily on improving feasibility and efficiency of split execution and adapter placement, without modeling task structure or incorporating multi-task personalization objectives.

ATLAS adds task-aware clustering, graph personalization, and dual-path aggregation on top of split-PEFT.


\subsection{System-Level FL Frameworks for LLMs}

Several recent frameworks study system-level aspects of FL and split learning for LLMs. VFLAIR-LLM provides an extensible split-LLM benchmark spanning multiple models, datasets, attacks, and defenses, and shows that mid-layer splits often preserve utility while enabling privacy-preserving inference and fine-tuning~\cite{vflair_llm}. TITANIC investigates production-grade FL with LLMs, highlighting challenges such as heterogeneous systems, scaling, and communication optimization in realistic deployments~\cite{titanic}.

These frameworks offer valuable insights into practical design trade-offs and provide tooling for evaluation, but they remain largely task-agnostic: clients are typically treated as a homogeneous population, and neither automatic task discovery nor graph-based personalization are tightly integrated into the optimization pipeline. In contrast, ATLAS targets a unified design that couples task-aware clustering, device-aware heterogeneous LoRA allocation, state-consistent split execution, dual-path aggregation, and Laplacian regularization over a fingerprint-derived task graph into a single, end-to-end FL framework for edge LLMs.

These frameworks offer insights but remain task-agnostic. ATLAS uniquely couples representation-based task discovery, heterogeneous LoRA, split execution, dual-path aggregation, and Laplacian regularization.

\section{Problem Formulation}
\label{sec:problem}

We consider a set of clients $\mathcal{K}=\{1,\dots,K\}$ and tasks $\mathcal{T}$.
Each client $k$ is associated with a task $t_k \in \mathcal{T}$ and local dataset
$D_k=\{(x_i^{(k)}, y_i^{(k)})\}$. Clients are heterogeneous in memory and communication budgets.

\subsection{Split Model and LoRA Adaptation}

We start from a pre-trained transformer model split at layer index $s$ into a client-side prefix $f_{\le s}$ (resides on client), and server-side suffix $f_{> s}$ (on server). For an input $x$:
\begin{equation}
h = f_{\le s}(x), \quad
u = f_{> s}(h), \quad
\hat{y} = h_{t_k}(u),
\end{equation}
where $h_{t_k}$ is a task-specific classification head.
To enable parameter-efficient personalization, each client $k$ trains LoRA adapters $A_k$
with layer-wise ranks $\{r_{\ell,k}\}_{\ell=1}^{L}$. We distinguish between client-personalized adapter parameters $A_k$ and cluster-shared non-LoRA parameters $U_{c_k}$ (server-side suffix/head parameters synchronized within cluster $c_k$).

\subsection{FMTL Objective with Graph Regularization}

We follow a federated multi-task learning (FMTL) objective:
\begin{equation}
\min_{A,U} \; J(A,U) = \sum_{k=1}^K f_k(A_k, U_{c_k}) + \eta R(A),
\label{eq:fmtl_objective}
\end{equation}
where $A_k$ denotes the personalized LoRA parameters for client $k$, $U_{c_k}$ denotes the shared non-LoRA parameters for cluster $c_k$, $\eta\ge 0$ controls coupling strength, and $R(A)$ is a Laplacian regularizer over a task graph:
\begin{equation}
R(A)=\frac{1}{2}\sum_{k=1}^K \sum_{\ell=1}^K a_{k\ell}\lVert A_k-A_\ell\rVert_2^2,
\end{equation}
with adjacency weights $a_{k\ell}\ge 0$ derived from task similarity. Restricting the regularizer to adapters avoids coupling time-inconsistent server-side classifier states in sequential split training~\cite{mira,splitfed,pfedme}.


\subsection{Device Constraints}

Each client $k$ has a memory budget $C_k^{\text{mem}}$; the LoRA configuration must satisfy:
\begin{equation}
\sum_{\ell=1}^{L} 2\, d_\ell\, r_{\ell,k}\, b_\ell \le C_k^{\text{mem}},
\label{eq:memory_constraint}
\end{equation}
where $d_\ell$ is the layer hidden dimension and $b_\ell$ captures datatype/overhead. In addition, ranks are selected from a discrete candidate set $\mathcal{R}=\{4,8,16,32,64\}$ and may be upper-bounded by a task-dependent cap $r^{\max}(t_k)$ for low-resource tasks.


\section{ATLAS Methodology}
\label{sec:methodology}

ATLAS implements a four-phase pipeline: (i) representation fingerprinting and task clustering, (ii) device-aware heterogeneous LoRA rank allocation under explicit budgets, (iii) split federated learning with task-aware aggregation and a heuristic weighted-score split selector, and (iv) Laplacian regularization over a fingerprint-derived task graph.

\subsection{Phase 1: Representation Fingerprinting and Task Clustering}
\label{subsec:phase1}

\textbf{Fingerprint extraction.}
Fingerprints should separate clients by task semantics before any federated averaging occurs. In the current ATLAS architecture, each client $k$ therefore computes a \emph{representation fingerprint} from a small number of local examples using the frozen backbone. For encoder models we use the [CLS] token embedding; for decoder-only models we use the analogous pooled final hidden-state representation. These raw sequence embeddings are averaged locally, then $\ell_2$-normalized and mean-centered across clients before cosine-based clustering~\cite{sbert}. We keep PCA compression as an optional fallback for high-dimensional fingerprint variants.


\textbf{Multi-metric cluster selection.} Given fingerprints $\{\mathbf{f}_k\}$, ATLAS runs $k$-means over a constrained candidate range $[k_\text{min}, k_\text{max}]$ and selects $k^*$ via
$$
\text{score}(k) = \alpha_\text{Sil} + \beta_\text{DB} + \gamma_\text{CH} - \lambda \cdot (\# \text{singletons}),
$$
where Sil/Davies-Bouldin (DB)/Calinski-Harabasz (CH) are normalized internal metrics ($\alpha,\beta,\gamma=1$ default; sum normalized), penalizing fragmented clusters. Outputs cluster assignments $c_k$, used in Phases 3--4.


Algorithm~\ref{alg:task_clustering} summarizes this three-step pipeline (representation extraction, normalization with optional compression, and multi-metric cluster selection).

\caption{Representation-Based Task Clustering in ATLAS}
\label{alg:task_clustering}
\begin{algorithmic}[1]
\Require Client set $\mathcal{K} = \{1, \ldots, K\}$, frozen backbone $\mathcal{M}_0$, local datasets $\{\mathcal{D}_k\}_{k=1}^K$
\Require Optional projection dimension $d$, cluster range $[k_{\min}, k_{\max}]$, fingerprint samples per client $S_f$
\Ensure Task clusters $\mathcal{C} = \{\mathcal{C}_1, \ldots, \mathcal{C}_{|\mathcal{C}|}\}$, assignments $\{c_k\}_{k=1}^K$
\State \textbf{Phase 1.1: Representation Fingerprints}
\For{each client $k \in \mathcal{K}$}
  \State Sample $S_f$ examples from $\mathcal{D}_k$
  \For{each sampled example or mini-batch $b$}
    \State Compute hidden representation $\mathbf{h}_{k,b} \leftarrow \textsc{Pool}(\mathcal{M}_0, b)$
  \EndFor
  \State Average raw embedding: $\mathbf{e}_k \leftarrow \frac{1}{S_f}\sum_b \mathbf{h}_{k,b}$
\EndFor
\State \textbf{Phase 1.2: Normalization / Optional Compression}
\State Stack embeddings $\mathbf{E} = [\mathbf{e}_1, \ldots, \mathbf{e}_K]^\top$
\State Optionally fit PCA on $\mathbf{E}$ and obtain projection matrix $\mathbf{U}_d$ when compression is enabled
\For{each client $k \in \mathcal{K}$}
  \State If compression is enabled, set $\mathbf{f}_k \leftarrow \mathbf{U}_d^\top \mathbf{e}_k$; otherwise set $\mathbf{f}_k \leftarrow \mathbf{e}_k$
  \State Normalize fingerprint: $\mathbf{f}_k \leftarrow \mathbf{f}_k / \|\mathbf{f}_k\|_2$
\EndFor
\State \textbf{Phase 1.3: Cluster Selection}
\State $\mathcal{F} \leftarrow [\mathbf{f}_1, \ldots, \mathbf{f}_K]^\top$, $\text{best\_score} \leftarrow -\infty$
\For{$n_c = k_{\min}$ to $k_{\max}$}
  \State Run $k$-means on $\mathcal{F}$ with $n_c$ clusters to obtain $\{\mathcal{C}_j^{(n_c)}\}_{j=1}^{n_c}$
  \State Compute internal clustering metrics and singleton count
  \State $s \leftarrow \textsc{MultiMetricScore}(\{\mathcal{C}_j^{(n_c)}\}_{j=1}^{n_c})$
  \If{$s > \text{best\_score}$}
    \State $\text{best\_score} \leftarrow s$, $\mathcal{C} \leftarrow \{\mathcal{C}_j^{(n_c)}\}_{j=1}^{n_c}$
  \EndIf
\EndFor
\State Derive assignments $c_k = j$ if $k \in \mathcal{C}_j$
\State \textbf{Return} $\mathcal{C}$ and $\{c_k\}_{k=1}^K$
\end{algorithmic}
\end{algorithm}


\subsection{Phase 2: Device-Aware Heterogeneous LoRA Rank Allocation}
\label{subsec:phase2}

Each client $k$ is associated with a device memory budget $M_k$. ATLAS converts it into an \emph{adapter budget} by reserving fractions for the frozen base model, activations, and optimizer state:
\begin{equation}
C^{\text{adpt}}_k = M_k \big(1-\alpha_{\text{base}}-\alpha_{\text{act}}-\alpha_{\text{opt}}\big).
\end{equation}
LoRA adapter memory for a layer with hidden size $d_{\ell}$ and rank $r_{\ell,k}$ is approximated by
\begin{equation}
M_{\ell}(r_{\ell,k}) \approx 2\, d_{\ell}\, r_{\ell,k}\, b,
\end{equation}
where $b$ depends on numeric precision and implementation overhead.

ATLAS injects LoRA into both attention and FFN projections so that client-side adaptation covers the full transformer block rather than attention alone~\cite{lora}. It derives per-layer importance weights from local adaptation statistics and allocates ranks from a discrete candidate set (e.g., $\{4,8,16,32,64\}$) under $C^{\text{adpt}}_k$ using an importance-aware, budget-constrained procedure: it finds the largest feasible uniform rank, converts it into a total rank budget, distributes it proportionally to importance, rounds to valid candidates, and downgrades least-important layers if needed to satisfy the budget. For small-data tasks, a task-adaptive cap $r^{\max}(t_k)$ prevents over-parameterized adapters from dominating scarce local supervision~\cite{lora,fah_qlora}.

\textbf{Illustration.} For 3 layers with $C_k^\text{adpt}$ allowing rank-sum $\approx 48$ and $\omega = [0.3, 0.5, 0.2]$, proportional allocation yields $r = [16, 24, 8]$ (downgrade least-important if over budget).

\subsection{Phase 3: Split Federated Learning with Heuristic Weighted-Score Split Selection}
\label{subsec:phase3}

\textbf{Split execution.}
ATLAS partitions the backbone at split layer $s$ into a client-side prefix and server-side suffix. In each local step, the client computes intermediate activations and sends them to the server; the server completes the forward pass, computes the loss, backpropagates through the suffix, and returns gradients w.r.t.\ the split activations. Clients update only their trainable components while keeping the base model frozen to reduce on-device cost. Because cluster members interact sequentially with a shared server-side suffix, ATLAS restores each client's stored server state at the beginning of its local turn and synchronizes the updated suffix back to that client at the end, following the state-consistency principle of SplitFed-style split FL~\cite{splitfed}. We further initialize cluster heads with deterministic Xavier weights and log-prior biases so that the split server begins from a stable, label-aware operating point rather than a degenerate zero-gradient regime~\cite{xavier}.

\textbf{Heuristic split selection (proxy-driven, constrained search).}
ATLAS evaluates candidate splits within a constrained set (avoiding extreme early/late cuts) and selects the split minimizing a weighted score:
\begin{equation}
\begin{aligned}
\mathrm{score}(s)
&= \alpha \,\mathrm{Mem}(s)
 + \beta \,\mathrm{Comm}(s) \\
&\quad + \gamma \,\mathrm{Imp}(s)
 + \delta \,\mathrm{Bal}(s),
\end{aligned}
\label{eq:split_score}
\end{equation}

where $\alpha, \beta, \gamma, \delta \ge 0$ and $\alpha + \beta + \gamma + \delta = 1$.

Here, $\alpha$ controls the emphasis on respecting client memory budgets,
$\beta$ penalizes communication-heavy splits, $\gamma$ weights
the (optional) importance proxy derived from representation fingerprints, and $\delta$
encourages balanced workload between client prefix and server suffix. The weights form a convex
combination ($\alpha + \beta + \gamma + \delta = 1$) and are treated as tunable hyperparameters.

Unless otherwise stated, we set $\alpha = 0.35$, $\beta = 0.30$, $\gamma = 0.25$, and $\delta = 0.10$.
These values were selected via preliminary sweeps on a validation configuration to prioritize
memory feasibility ($\alpha$) and communication reduction ($\beta$), while still allowing
importance ($\gamma$) and workload balance ($\delta$) to influence the split choice.

We observed that increasing $\alpha$ beyond $0.4$ tended to push splits too early
in the network (hurting accuracy), while decreasing $\beta$ below $0.2$
significantly increased activation traffic without accuracy gains.

Here, $\mathrm{Mem}(s)$ and $\mathrm{Comm}(s)$ are proxy estimates (budget check with safety margin and activation-transfer proxy), $\mathrm{Imp}(s)$ is optional (using representation or gradient signals when available, otherwise generic), and $\mathrm{Bal}(s)$ encourages balanced client/server workload.

\textbf{Task-aware aggregation and ablations.}
ATLAS aggregates updates \emph{within each Phase-1 cluster only}, but it does not use a single averaging rule for all trainable parameters. For heterogeneous-rank LoRA adapters, direct FedAvg can suppress higher-rank slices that low-rank clients never trained. ATLAS therefore uses rank-partitioned aggregation whenever adapters must be averaged explicitly (e.g., in non-Laplacian ablations):
\begin{equation}
\bar{A}_g^{(q)} \leftarrow \frac{1}{|\mathcal{S}_{g,q}|} \sum_{k \in \mathcal{S}_{g,q}} A_k^{(q)},
\qquad
\mathcal{S}_{g,q}=\{k \in g : r_k > q\},
\end{equation}
where $A_k^{(q)}$ is the $q$-th rank slice of client $k$'s adapter and only clients that instantiate that slice contribute to its average. In the full \texttt{atlas} path, adapters are instead personalized first by the Laplacian update on raw local weights, while shared non-LoRA parameters are averaged separately:
\begin{equation}
\bar{U}_g \leftarrow \sum_{k \in g} \tilde{\pi}_k\, U_k,
\qquad
\tilde{\pi}_k = \frac{\max(\pi_k,w_{\min})}{\sum_{j \in g}\max(\pi_j,w_{\min})},
\end{equation}
with $\pi_k$ denoting data- or performance-based client weights and $w_{\min}$ a minimum floor that prevents slow-converging clients from being eliminated by the aggregation rule~\cite{fednova,pfedme}.

\textbf{Communication-aware adapter exchange.}
Split execution introduces activation transfer, but the primary communication metric reported in the main ATLAS comparisons is \emph{LoRA synchronization traffic}, since this is the method-dependent overhead directly controlled by heterogeneous rank allocation and INT8 adapter exchange. LoRA parameters are quantized per output channel to INT8 for transmission, but they are always dequantized back to FP32 before any averaging or Laplacian arithmetic. This preserves the small inter-client differences required by graph regularization while retaining nearly $4\times$ compression relative to FP32 adapter exchange~\cite{llm_int8,qlora,zeroquant,smoothquant}.

This yields clean, implementation-faithful ablations:
(i) \texttt{fedavg\_cluster}: cluster-restricted averaging only (no split personalization, no Laplacian),
(ii) \texttt{atlas\_no\_laplacian}: split FL with heterogeneous ranks and rank-aware aggregation, without graph regularization,
(iii) \texttt{atlas}: dual-path aggregation with LoRA-only Laplacian personalization and shared-parameter averaging.

\subsection{Phase 4: Laplacian Regularization over a Fingerprint-Derived Task Graph}
\label{subsec:phase4}

ATLAS constructs a task graph from fingerprints and applies a MIRA-style Laplacian update for personalization. For clients $k$ and $\ell$, adjacency weights are computed using an RBF kernel:
\begin{equation}
a_{k\ell}=\exp\!\left(-\alpha \lVert f_k-f_\ell\rVert_2^2\right),
\end{equation}
then row-normalized so that $\sum_{\ell} a_{k\ell}=1$. 

By default, ATLAS enforces a block-diagonal graph using the selected clusters, thereby removing cross-cluster edges. In benchmark settings where task identifiers are available, the graph can be further filtered to same-task neighbors as a safeguard against impure cross-task couplings~\cite{cfl,ifca}. Singletons are connected to $K_\text{nn}$ nearest neighbors for connectivity.

Given client adapter parameters $A_k$, ATLAS applies the Laplacian to the raw local LoRA weights \emph{before} any cluster averaging:
\begin{equation}
A_k \leftarrow A_k - \eta \sum_{\ell} a_{k\ell}(A_k-A_\ell),
\end{equation}
where $\eta$ controls the coupling strength. Applying the update on pre-aggregation local adapters avoids the degenerate zero-regularization case that occurs if all cluster members are first averaged to the same point~\cite{mira,scaffold,pfedme}. This nudges similar clients to align while preserving task-specific personalization.

\begin{algorithm}[!t]
\caption{Task Graph Construction with RBF Kernel}
\label{alg:task_graph}
\begin{algorithmic}[1]
\Require Fingerprints $\{\mathbf{f}_k\}_{k=1}^K$, cluster assignments $\{c_k\}_{k=1}^K$
\Require RBF bandwidth $\alpha$, neighbor budget $K_{\text{nn}}$
\Ensure Adjacency matrix $\mathbf{A} = [a_{k\ell}]_{K \times K}$
\State Initialize $\mathbf{A} \leftarrow \mathbf{0}_{K \times K}$
\For{each client $k \in \mathcal{K}$}
  \State $\mathcal{T}_k \leftarrow \{\ell : c_\ell = c_k\}$ \Comment{Same-cluster clients}
  \State Compute similarities $s_{k\ell} = \exp(-\alpha \|\mathbf{f}_k - \mathbf{f}_\ell\|_2^2)$ for $\ell \in \mathcal{T}_k \setminus \{k\}$
  \State $\mathcal{N}_k \leftarrow \text{TopK}(\{s_{k\ell}\}, K_{\text{nn}})$
  \State Normalize: $a_{k\ell} \leftarrow s_{k\ell} / \sum_{j \in \mathcal{N}_k} s_{kj}$ for $\ell \in \mathcal{N}_k$
\EndFor
\State Symmetrize: $a_{k\ell} \leftarrow (a_{k\ell} + a_{\ell k}) / 2$ for all $k,\ell$
\State \textbf{Return} $\mathbf{A}$
\end{algorithmic}
\end{algorithm}

\textbf{Heterogeneous rank handling.} To align adapters across clients with varying ranks $r_{k\ell} \neq r_{k'\ell}$, ATLAS computes the Laplacian in the shared low-rank subspace only. For a client pair $(k,\ell)$, let $r_{\min}=\min(r_k,r_\ell)$; the LoRA difference is evaluated on the first $r_{\min}$ rows/columns and the resulting update is zero-padded back to client $k$'s native rank. This preserves high-rank client capacity while regularizing the common subspace shared with its neighbors.

\begin{algorithm}[!t]
\caption{Laplacian Regularization with Heterogeneous LoRA Ranks}
\label{alg:laplacian_aggregation}
\begin{algorithmic}[1]
\Require Client adapters $\{\mathbf{A}_k^{(t)}\}_{k=1}^K$ after local training at round $t$
\Require Task graph $\mathcal{G} = (\mathcal{K}, \mathcal{E})$ with weights $\{a_{k\ell}\}$
\Require Regularization strength $\eta$
\Require Layer importance weights $\{\omega_\ell\}_{\ell \in \mathcal{L}}$
\Ensure Updated adapters $\{\mathbf{A}_k^{(t+1)}\}_{k=1}^K$
\State Each $\mathbf{A}_k^{(t)} = \{\boldsymbol{\theta}_k^{\ell,(t)}\}_{\ell \in \mathcal{L}}$ \Comment{LoRA blocks}
\For{each client $k \in \mathcal{K}$}
  \State $\mathcal{N}_k \leftarrow \{\ell : (k,\ell) \in \mathcal{E}\}$ \Comment{Neighbors}
  \If{$|\mathcal{N}_k| = 0$}
    \State $\mathbf{A}_k^{(t+1)} \leftarrow \mathbf{A}_k^{(t)}$ \Comment{No Laplacian update}
    \State \textbf{continue}
  \EndIf
  \For{each layer $\ell \in \mathcal{L}$}
    \State $\Delta \boldsymbol{\theta}_k^\ell \leftarrow 0$
    \For{each neighbor $j \in \mathcal{N}_k$}
      \State $r_{\min} \leftarrow \min(r_{k,\ell}, r_{j,\ell})$
      \State $(\hat{\boldsymbol{\theta}}_k^\ell, \hat{\boldsymbol{\theta}}_j^\ell) \leftarrow \textsc{SharedSubspace}(\boldsymbol{\theta}_k^{\ell,(t)}, \boldsymbol{\theta}_j^{\ell,(t)}, r_{\min})$
      \State $\lambda_{kj} \leftarrow \omega_\ell \cdot a_{kj}$
      \State $\Delta \boldsymbol{\theta}_k^\ell \leftarrow \Delta \boldsymbol{\theta}_k^\ell + \lambda_{kj} (\hat{\boldsymbol{\theta}}_k^\ell - \hat{\boldsymbol{\theta}}_j^\ell)$
    \EndFor
    \State $\boldsymbol{\theta}_k^{\ell,(t+1)} \leftarrow \boldsymbol{\theta}_k^{\ell,(t)} - \eta \cdot \Delta \boldsymbol{\theta}_k^\ell$
  \EndFor
  \State $\mathbf{A}_k^{(t+1)} \leftarrow \{\boldsymbol{\theta}_k^{\ell,(t+1)}\}_{\ell \in \mathcal{L}}$
\EndFor
\State \textbf{Return} $\{\mathbf{A}_k^{(t+1)}\}_{k=1}^K$
\end{algorithmic}
\end{algorithm}

\subsection{Tasks, Data, and Client Federation}

We evaluate ATLAS in a heterogeneous multi-task FL setting using three GLUE sentence classification tasks: SST-2 (sentiment analysis), MRPC (paraphrase detection), and QNLI (question natural language inference)~\cite{glue}. Each client is assigned to exactly one task and trains only on its local data; no raw data are shared.

We simulate a federation of $K=9$ clients (3 clients per task) with heterogeneous device profiles emulating 2--16~GB memory budgets. Unless otherwise noted, each client uses up to 3{,}000 local training samples (subsampled if necessary) to control runtime variance across tasks and models.

\subsection{Training Protocol}

Fingerprints are extracted from frozen-backbone sequence embeddings, cluster heads are initialized with deterministic Xavier weights plus log-prior biases, and the Laplacian is enabled after a one-round warmup. We run federated training for 10 communication rounds with 2 local epochs per round. The main comparisons are reported over seeds $\{42, 123, 456\}$.

\subsection{Communication and Robustness}

ATLAS also improves communication efficiency. Relative to standard FedAvg, LoRA synchronization traffic drops from 889.3~MB to 611.4~MB on DistilBERT (0.69$\times$), from 827.4~MB to 554.7~MB on GPT-2 (0.67$\times$), and from 4070.9~MB to 1154.0~MB on Qwen-2.5-0.5B (0.28$\times$). The largest absolute reduction occurs on Qwen, where ATLAS reduces synchronization traffic by 2916.9~MB while still improving the macro-average score.

Robustness to device heterogeneity also improves materially. In all three backbone families, standard FedAvg drops an average of 2 weak-device clients out of 9, while ATLAS drops none. Figure~\ref{fig:client_failures} shows that these failures are not isolated outliers but a recurring pattern under the baseline. This matters because a heterogeneous FL method that achieves high accuracy only by excluding weaker devices does not satisfy the motivating systems constraint.

\subsection{Ablation on GPT-2}

The GPT-2 ablation provides component-level evidence for the ATLAS design. Table~\ref{tab:ablation_deltas} shows that progressively adding task-aware clustering, heterogeneous ranks, split learning, and Laplacian personalization improves the final result. Relative to standard FedAvg, \texttt{fedavg\_cluster} improves the macro-average from 0.5605 to 0.6943, indicating that restricting collaboration to task-consistent groups already mitigates substantial negative transfer. Adding the remaining ATLAS pipeline without Laplacian increases the macro-average further to 0.7878. The full ATLAS run reaches $0.8088 \pm 0.0158$, and the experimental analysis attributes an additional +0.0210 macro-average accuracy to the Laplacian component over \texttt{atlas\_no\_laplacian}.

\subsection{Discussion}

The completed study supports three main conclusions. First, the ATLAS pipeline consistently outperforms standard FedAvg across encoder and decoder backbones, suggesting that the method is not tied to a single architecture family. Second, the gains are accompanied by lower LoRA synchronization traffic and the elimination of weak-device dropouts, which strengthens the systems argument rather than reducing the contribution to a pure accuracy story. Third, the GPT-2 ablation indicates that the performance gain is not attributable to a single isolated trick: task-aware clustering delivers the first large improvement, the full heterogeneous split pipeline yields a larger one, and Laplacian personalization contributes a further but smaller gain.
