\begin{abstract}
Federated learning (FL) enables on-device adaptation of large language models (LLMs) without centralizing sensitive data, yet practical deployment on heterogeneous edge devices is challenged by task diversity, resource constraints, and high communication overhead. Naïve task-agnostic aggregation (e.g., FedAvg) and uniform-rank low-rank adaptation (LoRA) may suffer from negative transfer, suboptimal personalization, and inefficient utilization of device budgets.

This paper presents \textbf{ATLAS}, an adaptive task-aware FL framework for parameter-efficient fine-tuning of transformer-based LLMs on heterogeneous clients. ATLAS integrates four phases: (i) gradient-based task clustering via compact fingerprints, (ii) device-aware heterogeneous LoRA rank allocation under explicit memory budgets, (iii) split federated learning with adaptive split selection and per-cluster aggregation, and (iv) MIRA-style Laplacian regularization over an RBF-kernel task graph derived from fingerprints.

We implement ATLAS in an end-to-end pipeline and prepare a reproducible evaluation on GLUE classification tasks with heterogeneous client profiles~\cite{glue}. Experimental results and statistical analysis will be reported upon completion of the ongoing runs.
\end{abstract}

\begin{IEEEkeywords}
Federated learning, large language models, LoRA, split learning, multi-task learning, personalization.
\end{IEEEkeywords}

\section{Introduction}

\IEEEPARstart{F}{ederated} learning (FL) enables collaborative model adaptation without centralizing user data, making it attractive for privacy-sensitive on-device personalization. However, federated adaptation of transformer-based large language models (LLMs) on heterogeneous edge devices is constrained by three coupled factors: (i) \emph{task heterogeneity} across clients, (ii) \emph{resource heterogeneity} (memory/compute), and (iii) \emph{communication bottlenecks} that make full-model synchronization impractical.

Task heterogeneity leads to \emph{negative transfer} when a single global model is optimized across diverse NLP tasks, such as sentiment analysis, paraphrase detection, and grammatical acceptability. Classical FL methods such as FedAvg focus on a single global objective, which can degrade both global quality and per-client personalization when client objectives differ substantially~\cite{fedavg}. Federated multi-task learning (FMTL) frameworks instead enforce structured sharing across related clients or tasks, often using graph-based couplings to preserve task-specific specialization while still leveraging common structure~\cite{mira}.

At the same time, edge devices exhibit strong variation in memory, compute, and network bandwidth, which makes full-model fine-tuning of LLMs impractical in many realistic deployments. Parameter-efficient fine-tuning (PEFT) methods such as LoRA reduce the number of trainable parameters by injecting low-rank adapters into selected layers, thereby lowering memory and often communication costs when only adapters are exchanged~\cite{lora}. Complementary strategies such as split learning partition the model between clients and a server, offloading deep layers and most of the backpropagation to the server to further reduce client-side load.

Existing work has explored FMTL (e.g., MIRA~\cite{mira}), PEFT under device constraints (e.g., FAH-QLoRA~\cite{fah_qlora}), and split federated learning (e.g., SplitLoRA/HSplitLoRA/TITANIC~\cite{splitlora,hsplitlora,titanic}, largely in isolation. These lack a jointly task-aware and device-aware design that automatically discovers task structure, allocates heterogeneous adapters, leverages splits, and applies task couplings.

This paper presents \textbf{ATLAS}, an adaptive task-aware FL framework for parameter-efficient fine-tuning of transformer-based LLMs on heterogeneous clients. ATLAS integrates four phases: (i) gradient-based task clustering via compact fingerprints, (ii) device-aware heterogeneous LoRA rank allocation under explicit memory budgets, (iii) split federated learning with adaptive split selection and per-cluster aggregation, and (iv) MIRA-style Laplacian regularization over an RBF-kernel task graph derived from fingerprints.

We implement ATLAS in an end-to-end pipeline and prepare a reproducible evaluation on GLUE classification tasks with heterogeneous client profiles. Experimental results and statistical analysis will be reported upon completion of the ongoing runs.

\textbf{Contributions.}
ATLAS makes the following contributions:
\begin{itemize}
\item Task-aware clustering from gradient fingerprints: ATLAS derives compact 64-D PCA-projected gradient fingerprints and selects clusters with a multi-metric criterion that penalizes fragmentation ($\lambda \times \#$singletons), mitigating cross-task negative transfer in multi-task FL.
\item Heterogeneous LoRA under explicit budgets: ATLAS allocates per-layer LoRA ranks from discrete candidates under a per-device adapter memory budget, using importance signals from gradient statistics, maximizing utilization on heterogeneous devices.
\item Split FL with heuristic weighted-score split selection: ATLAS selects splits via a budget- and proxy-driven heuristic combining memory, communication, importance, and balance terms, then performs per-cluster aggregation (no cross-cluster averaging).
\item Graph-based personalization: ATLAS applies a MIRA-style Laplacian regularization using an RBF-kernel graph from fingerprints to couple similar clients while preserving personalization.
\end{itemize}

\section{Related Work}
\label{sec:related}

\subsection{Federated Multi-Task Learning and Personalization}

Classical FL algorithms such as FedAvg optimize a single global objective by averaging client updates across all participants~\cite{fedavg}. When clients solve different but related NLP tasks, na\"{i}ve global averaging can induce negative transfer, where updates from one task harm performance on another, ultimately degrading both global quality and per-client personalization.

Federated multi-task learning (FMTL) aims to mitigate this by introducing structured sharing across tasks rather than uniform mixing. MIRA, for instance, introduces graph-based coupling via Laplacian regularization, encouraging similar tasks to remain close in parameter space while preserving per-task specialization~\cite{mira}. However, MIRA assumes that each client can store and fine-tune an entire model, which becomes unrealistic when the backbone is a multi-billion-parameter LLM and many clients are memory-constrained edge devices.

ATLAS borrows the Laplacian idea but adapts it to (i) LoRA-only personalization, (ii) fingerprint-derived graphs, and (iii) split execution on constrained devices.


\subsection{Parameter-Efficient Fine-Tuning under Device Constraints}

Parameter-efficient fine-tuning (PEFT) techniques such as LoRA reduce fine-tuning cost by injecting low-rank adapters into selected layers while keeping the base model frozen~\cite{lora}. This design significantly lowers the number of trainable parameters and can reduce communication when only adapters are shared, but most existing deployments use \emph{uniform} ranks across layers and devices, which can exceed the capacity of low-end hardware and underutilize high-end devices.

Recent work on federated adaptation of LLMs combines LoRA with quantization and heterogeneous configurations to better match device capabilities. FAH-QLoRA, for example, explores joint design of quantization schemes and LoRA adapters, enabling adaptive configurations across clients with different budgets~\cite{fah_qlora}. Nonetheless, these approaches typically remain task-agnostic at the federation level: aggregation is still performed globally across all clients, and there is no explicit mechanism to prevent cross-task mixing via clustering or graph-based personalization.

ATLAS is task-aware via clustering + graph regularization, atop heterogeneous LoRA.


\subsection{Split Learning and Split-PEFT for LLMs}

Split learning partitions a model into a client-side prefix and a server-side suffix, allowing clients to compute early-layer activations while offloading deeper layers, loss computation, and most of backpropagation to a powerful server. This paradigm is appealing for edge LLMs because it reduces client memory and compute requirements without fully sacrificing privacy.

Basic split-PEFT methods combine model splitting with LoRA-style adapters to further decrease client-side state. SplitLoRA and HSplitLoRA, for instance, integrate split learning with LoRA adapters to reduce client memory by 50--70\% and to enable heterogeneous rank allocation while keeping accuracy close to centralized fine-tuning~\cite{splitlora,hsplitlora}. However, these methods focus primarily on improving feasibility and efficiency of split execution and adapter placement, without modeling task structure or incorporating multi-task personalization objectives.

ATLAS adds task-aware clustering and graph personalization atop split-PEFT.


\subsection{System-Level FL Frameworks for LLMs}

Several recent frameworks study system-level aspects of FL and split learning for LLMs. VFLAIR-LLM provides an extensible split-LLM benchmark spanning multiple models, datasets, attacks, and defenses, and shows that mid-layer splits often preserve utility while enabling privacy-preserving inference and fine-tuning~\cite{vflair_llm}. TITANIC investigates production-grade FL with LLMs, highlighting challenges such as heterogeneous systems, scaling, and communication optimization in realistic deployments~\cite{titanic}.

These frameworks offer valuable insights into practical design trade-offs and provide tooling for evaluation, but they remain largely task-agnostic: clients are typically treated as a homogeneous population, and neither automatic task discovery nor graph-based personalization are tightly integrated into the optimization pipeline. In contrast, ATLAS targets a unified design that couples task-aware clustering, device-aware heterogeneous LoRA allocation, split execution, and Laplacian regularization over a fingerprint-derived task graph into a single, end-to-end FL framework for edge LLMs.

These frameworks offer insights but remain task-agnostic. ATLAS uniquely couples task-aware clustering, heterogeneous LoRA, split execution, and Laplacian regularization.

\section{Problem Formulation}
\label{sec:problem}

We consider a set of clients $\mathcal{K}=\{1,\dots,K\}$ and tasks $\mathcal{T}$.
Each client $k$ is associated with a task $t_k \in \mathcal{T}$ and local dataset
$D_k=\{(x_i^{(k)}, y_i^{(k)})\}$. Clients are heterogeneous in memory and communication budgets.

\subsection{Split Model and LoRA Adaptation}

We start from a pre-trained transformer model split at layer index $s$ into a client-side prefix $f_{\le s}$ (resides on client), and server-side suffix $f_{> s}$ (on server). For an input $x$:
\begin{equation}
h = f_{\le s}(x), \quad
u = f_{> s}(h), \quad
\hat{y} = h_{t_k}(u),
\end{equation}
where $h_{t_k}$ is a task-specific classification head.
To enable parameter-efficient personalization, each client $k$ trains LoRA adapters $A_k$
with layer-wise ranks $\{r_{\ell,k}\}_{\ell=1}^{L}$.

\subsection{FMTL Objective with Graph Regularization}

We follow a federated multi-task learning (FMTL) objective:
\begin{equation}
\min_{W} \; J(W) = \sum_{k=1}^K f_k(w_k) + \eta R(W),
\label{eq:fmtl_objective}
\end{equation}
where $w_k$ denotes the trainable parameters (LoRA + head; base frozen) for client $k$,
$\eta\ge 0$ controls coupling strength, and $R(W)$ is a Laplacian regularizer over a task graph:
\begin{equation}
R(W)=\frac{1}{2}\sum_{k=1}^K \sum_{\ell=1}^K a_{k\ell}\lVert w_k-w_\ell\rVert_2^2,
\end{equation}
with adjacency weights $a_{k\ell}\ge 0$ derived from task similarity.


\subsection{Device Constraints}

Each client $k$ has a memory budget $C_k^{\text{mem}}$; the LoRA configuration must satisfy:
\begin{equation}
\sum_{\ell=1}^{L} 2\, d_\ell\, r_{\ell,k}\, b_\ell \le C_k^{\text{mem}},
\label{eq:memory_constraint}
\end{equation}
where $d_\ell$ is the layer hidden dimension and $b_\ell$ captures datatype/overhead.


\section{ATLAS Methodology}
\label{sec:methodology}

ATLAS implements a four-phase pipeline: (i) gradient fingerprinting and task clustering, (ii) device-aware heterogeneous LoRA rank allocation under explicit budgets, (iii) split federated learning with task-aware aggregation and a heuristic weighted-score split selector, and (iv) Laplacian regularization over a fingerprint-derived task graph.

\subsection{Phase 1: Gradient Fingerprinting and Task Clustering}
\label{subsec:phase1}

\textbf{Fingerprint extraction.}
Fingerprints capture task-specific gradient structure so similar loss landscapes cluster together without shared labels.
For each client $k$, ATLAS computes a compact \emph{gradient fingerprint} from a small number of mini-batches. Gradients are collected from task-relevant late layers (and the classifier), aggregated across batches, and layer-wise normalized to avoid domination by large tensors. The resulting vector is projected to a fixed dimensionality of $d_f=64$ using PCA (fit once per federation as pre-processing), yielding a fingerprint $\mathbf{f}_k \in \mathbb{R}^{64}$.


\textbf{Multi-metric cluster selection.} Given fingerprints $\{\mathbf{f}_k\}$, ATLAS runs $k$-means over a constrained candidate range $[k_\text{min}, k_\text{max}]$ and selects $k^*$ via
$$
\text{score}(k) = \alpha_\text{Sil} + \beta_\text{DB} + \gamma_\text{CH} - \lambda \cdot (\# \text{singletons}),
$$
where Sil/Davies-Bouldin (DB)/Calinski-Harabasz (CH) are normalized internal metrics ($\alpha,\beta,\gamma=1$ default; sum normalized), penalizing fragmented clusters. Outputs cluster assignments $c_k$, used in Phases 3--4.


Algorithm~\ref{alg:task_clustering} summarizes this three‑step pipeline (fingerprint extraction, PCA projection, and multi‑metric cluster selection).

\begin{algorithm}[!t]
\caption{Gradient-Based Task Clustering in ATLAS}
\label{alg:task_clustering}
\begin{algorithmic}[1]
\Require Client set $\mathcal{K} = \{1, \ldots, K\}$, base model $\mathcal{M}_0$, local datasets $\{\mathcal{D}_k\}_{k=1}^K$
\Require PCA dimension $d$, cluster range $[k_{\min}, k_{\max}]$, fingerprint samples per client $S_f$
\Ensure Task clusters $\mathcal{C} = \{\mathcal{C}_1, \ldots, \mathcal{C}_{|\mathcal{C}|}\}$, assignments $\{c_k\}_{k=1}^K$
\State \textbf{Phase 1.1: Gradient Fingerprints}
\For{each client $k \in \mathcal{K}$}
  \State Initialize local model: $\mathcal{M}_k \leftarrow \mathcal{M}_0$
  \State Sample mini-batch $\mathcal{B}_k \sim \mathcal{D}_k$ with $|\mathcal{B}_k| = S_f$
  \For{each layer $\ell \in \mathcal{L}$}
    \State Compute gradient $\nabla_{\mathbf{W}_\ell} \mathcal{L}(\mathcal{M}_k; \mathcal{B}_k)$
    \State Normalize and store $\tilde{\mathbf{g}}_\ell$ in $\mathbf{g}_k^{\text{raw}}[\ell]$
  \EndFor
  \State Flatten $\mathbf{g}_k \leftarrow \text{concat}(\{\mathbf{g}_k^{\text{raw}}[\ell]\}_{\ell \in \mathcal{L}})$
\EndFor
\State \textbf{Phase 1.2: PCA Fingerprints}
\State Stack gradients $\mathbf{G} = [\mathbf{g}_1, \ldots, \mathbf{g}_K]^\top$
\State Fit PCA on $\mathbf{G}$ and obtain projection matrix $\mathbf{U}_d$
\For{each client $k \in \mathcal{K}$}
  \State Project and normalize fingerprint: $\mathbf{f}_k \leftarrow \mathbf{U}_d^\top \mathbf{g}_k$, $\mathbf{f}_k \leftarrow \mathbf{f}_k / \|\mathbf{f}_k\|_2$
\EndFor
\State \textbf{Phase 1.3: Cluster Selection}
\State $\mathcal{F} \leftarrow [\mathbf{f}_1, \ldots, \mathbf{f}_K]^\top$, $\text{best\_score} \leftarrow -\infty$
\For{$n_c = k_{\min}$ to $k_{\max}$}
  \State Run $k$-means on $\mathcal{F}$ with $n_c$ clusters to obtain $\{\mathcal{C}_j^{(n_c)}\}_{j=1}^{n_c}$
  \State Compute internal clustering metrics and singleton count
  \State $s \leftarrow \textsc{MultiMetricScore}(\{\mathcal{C}_j^{(n_c)}\}_{j=1}^{n_c})$
  \If{$s > \text{best\_score}$}
    \State $\text{best\_score} \leftarrow s$, $\mathcal{C} \leftarrow \{\mathcal{C}_j^{(n_c)}\}_{j=1}^{n_c}$
  \EndIf
\EndFor
\State Derive assignments $c_k = j$ if $k \in \mathcal{C}_j$
\State \textbf{Return} $\mathcal{C}$ and $\{c_k\}_{k=1}^K$
\end{algorithmic}
\end{algorithm}


\subsection{Phase 2: Device-Aware Heterogeneous LoRA Rank Allocation}
\label{subsec:phase2}

Each client $k$ is associated with a device memory budget $M_k$. ATLAS converts it into an \emph{adapter budget} by reserving fractions for the frozen base model, activations, and optimizer state:
\begin{equation}
C^{\text{adpt}}_k = M_k \big(1-\alpha_{\text{base}}-\alpha_{\text{act}}-\alpha_{\text{opt}}\big).
\end{equation}
LoRA adapter memory for a layer with hidden size $d_{\ell}$ and rank $r_{\ell,k}$ is approximated by
\begin{equation}
M_{\ell}(r_{\ell,k}) \approx 2\, d_{\ell}\, r_{\ell,k}\, b,
\end{equation}
where $b$ depends on numeric precision and implementation overhead.

ATLAS derives per-layer importance weights from the same gradient statistics as fingerprints collected in Phase 1 (squared gradient norms aggregated per layer during fingerprinting). It then allocates ranks from a discrete candidate set (e.g., $\{4,8,16,32,64\}$) under $C^{\text{adpt}}_k$ using an importance-aware, budget-constrained procedure: it finds the largest feasible uniform rank, converts it into a total rank budget, distributes it proportionally to importance, rounds to valid candidates, and downgrades least-important layers if needed to satisfy the budget.

\textbf{Illustration.} For 3 layers with $C_k^\text{adpt}$ allowing rank-sum $\approx 48$ and $\omega = [0.3, 0.5, 0.2]$, proportional allocation yields $r = [16, 24, 8]$ (downgrade least-important if over budget).

\subsection{Phase 3: Split Federated Learning with Heuristic Weighted-Score Split Selection}
\label{subsec:phase3}

\textbf{Split execution.}
ATLAS partitions the backbone at split layer $s$ into a client-side prefix and server-side suffix. In each local step, the client computes intermediate activations and sends them to the server; the server completes the forward pass, computes the loss, backpropagates through the suffix, and returns gradients w.r.t.\ the split activations. Clients update only their trainable components (LoRA adapters and optionally task heads), while keeping the base model frozen to reduce on-device cost.

\textbf{Heuristic split selection (proxy-driven, constrained search).}
ATLAS evaluates candidate splits within a constrained set (avoiding extreme early/late cuts) and selects the split minimizing a weighted score:
\begin{equation}
\begin{aligned}
\mathrm{score}(s)
&= \alpha \,\mathrm{Mem}(s)
 + \beta \,\mathrm{Comm}(s) \\
&\quad + \gamma \,\mathrm{Imp}(s)
 + \delta \,\mathrm{Bal}(s),
\end{aligned}
\label{eq:split_score}
\end{equation}

where $\alpha, \beta, \gamma, \delta \ge 0$ and $\alpha + \beta + \gamma + \delta = 1$.

Here, $\alpha$ controls the emphasis on respecting client memory budgets,
$\beta$ penalizes communication-heavy splits, $\gamma$ weights
the (optional) importance proxy derived from gradient fingerprints, and $\delta$
encourages balanced workload between client prefix and server suffix. The weights form a convex
combination ($\alpha + \beta + \gamma + \delta = 1$) and are treated as tunable hyperparameters.

Unless otherwise stated, we set $\alpha = 0.35$, $\beta = 0.30$, $\gamma = 0.25$, and $\delta = 0.10$.
These values were selected via preliminary sweeps on a validation configuration to prioritize
memory feasibility ($\alpha$) and communication reduction ($\beta$), while still allowing
importance ($\gamma$) and workload balance ($\delta$) to influence the split choice.

We observed that increasing $\alpha$ beyond $0.4$ tended to push splits too early
in the network (hurting accuracy), while decreasing $\beta$ below $0.2$
significantly increased activation traffic without accuracy gains.

Here, $\mathrm{Mem}(s)$ and $\mathrm{Comm}(s)$ are proxy estimates (budget check with safety margin and activation-transfer proxy), $\mathrm{Imp}(s)$ is optional (using fingerprint/gradient signals when available, otherwise generic), and $\mathrm{Bal}(s)$ encourages balanced client/server workload.

\textbf{Task-aware aggregation and ablations.}
After local updates, ATLAS aggregates model updates \emph{within each Phase-1 cluster only} (per-cluster FedAvg), with no cross-cluster averaging:
\begin{equation}
A_g \leftarrow \sum_{k \in g} \frac{n_k}{\sum_{j \in g} n_j}\, A_k,
\end{equation}
where $A_k$ denotes client $k$'s adapter parameters, $g$ is a cluster, and $n_k$ is the local dataset size.
This yields clean, implementation-faithful ablations:
(i) \texttt{local\_only}: local training with no aggregation (communication is zero),
(ii) \texttt{fedavg\_cluster}: per-cluster FedAvg only (no Laplacian),
(iii) \texttt{atlas}: per-cluster FedAvg plus Laplacian personalization.

\subsection{Phase 4: Laplacian Regularization over a Fingerprint-Derived Task Graph}
\label{subsec:phase4}

ATLAS constructs a task graph from fingerprints and applies a MIRA-style Laplacian update for personalization. For clients $k$ and $\ell$, adjacency weights are computed using an RBF kernel:
\begin{equation}
a_{k\ell}=\exp\!\left(-\alpha \lVert f_k-f_\ell\rVert_2^2\right),
\end{equation}
then row-normalized so that $\sum_{\ell} a_{k\ell}=1$. 

Default: block-diagonal structure (enforced, removes cross-cluster edges); connect singletons to $K_\text{nn}$ nearest neighbors for connectivity.

Given client parameters $w_k$ (e.g., LoRA and head parameters), ATLAS applies:
\begin{equation}
w_k \leftarrow w_k - \eta \sum_{\ell} a_{k\ell}(w_k-w_\ell),
\end{equation}
where $\eta$ controls the coupling strength. This nudges similar clients to align while preserving task-specific personalization.

\begin{algorithm}[!t]
\caption{Task Graph Construction with RBF Kernel}
\label{alg:task_graph}
\begin{algorithmic}[1]
\Require Fingerprints $\{\mathbf{f}_k\}_{k=1}^K$, cluster assignments $\{c_k\}_{k=1}^K$
\Require RBF bandwidth $\alpha$, neighbor budget $K_{\text{nn}}$
\Ensure Adjacency matrix $\mathbf{A} = [a_{k\ell}]_{K \times K}$
\State Initialize $\mathbf{A} \leftarrow \mathbf{0}_{K \times K}$
\For{each client $k \in \mathcal{K}$}
  \State $\mathcal{T}_k \leftarrow \{\ell : c_\ell = c_k\}$ \Comment{Same-cluster clients}
  \State Compute similarities $s_{k\ell} = \exp(-\alpha \|\mathbf{f}_k - \mathbf{f}_\ell\|_2^2)$ for $\ell \in \mathcal{T}_k \setminus \{k\}$
  \State $\mathcal{N}_k \leftarrow \text{TopK}(\{s_{k\ell}\}, K_{\text{nn}})$
  \State Normalize: $a_{k\ell} \leftarrow s_{k\ell} / \sum_{j \in \mathcal{N}_k} s_{kj}$ for $\ell \in \mathcal{N}_k$
\EndFor
\State Symmetrize: $a_{k\ell} \leftarrow (a_{k\ell} + a_{\ell k}) / 2$ for all $k,\ell$
\State \textbf{Return} $\mathbf{A}$
\end{algorithmic}
\end{algorithm}

\textbf{Heterogeneous rank handling.} To align adapters across clients with varying ranks $r_{k\ell} \neq r_{k'\ell}$, ATLAS uses rank-alignment mode $\rho \in \{\text{pad\_to\_max}, \text{clip\_to\_min}, \text{proj}\}$ (zero-padding to max rank, clipping to min, or projection to shared subspace). Laplacian runs server-side on per-cluster aggregated adapters, pre-global FedAvg.

\begin{algorithm}[!t]
\caption{Laplacian Regularization with Heterogeneous LoRA Ranks}
\label{alg:laplacian_aggregation}
\begin{algorithmic}[1]
\Require Client adapters $\{\mathbf{W}_k^{(t)}\}_{k=1}^K$ after local training at round $t$
\Require Task graph $\mathcal{G} = (\mathcal{K}, \mathcal{E})$ with weights $\{a_{k\ell}\}$
\Require Regularization strength $\eta$, rank-alignment mode $\rho$
\Require Layer importance weights $\{\omega_\ell\}_{\ell \in \mathcal{L}}$
\Ensure Updated adapters $\{\mathbf{W}_k^{(t+1)}\}_{k=1}^K$
\State Each $\mathbf{W}_k^{(t)} = \{\boldsymbol{\theta}_k^{\ell,(t)}\}_{\ell \in \mathcal{L}}$ \Comment{LoRA blocks}
\For{each client $k \in \mathcal{K}$}
  \State $\mathcal{N}_k \leftarrow \{\ell : (k,\ell) \in \mathcal{E}\}$ \Comment{Neighbors}
  \If{$|\mathcal{N}_k| = 0$}
    \State $\mathbf{W}_k^{(t+1)} \leftarrow \mathbf{W}_k^{(t)}$ \Comment{No Laplacian update}
    \State \textbf{continue}
  \EndIf
  \For{each layer $\ell \in \mathcal{L}$}
    \State $\Delta \boldsymbol{\theta}_k^\ell \leftarrow 0$
    \For{each neighbor $j \in \mathcal{N}_k$}
      \State $(\hat{\boldsymbol{\theta}}_k^\ell, \hat{\boldsymbol{\theta}}_j^\ell) \leftarrow \textsc{AlignRanks}(\boldsymbol{\theta}_k^{\ell,(t)}, \boldsymbol{\theta}_j^{\ell,(t)}, \rho)$
      \State $\lambda_{kj} \leftarrow \omega_\ell \cdot a_{kj}$
      \State $\Delta \boldsymbol{\theta}_k^\ell \leftarrow \Delta \boldsymbol{\theta}_k^\ell + \lambda_{kj} (\hat{\boldsymbol{\theta}}_k^\ell - \hat{\boldsymbol{\theta}}_j^\ell)$
    \EndFor
    \State $\boldsymbol{\theta}_k^{\ell,(t+1)} \leftarrow \boldsymbol{\theta}_k^{\ell,(t)} - \eta \cdot \Delta \boldsymbol{\theta}_k^\ell$
  \EndFor
  \State $\mathbf{W}_k^{(t+1)} \leftarrow \{\boldsymbol{\theta}_k^{\ell,(t+1)}\}_{\ell \in \mathcal{L}}$
\EndFor
\State \textbf{Return} $\{\mathbf{W}_k^{(t+1)}\}_{k=1}^K$
\end{algorithmic}
\end{algorithm}

\subsection{Baselines and Progressive Ablation Study}

To compare ``everything'' while keeping the study interpretable, we adopt a progressive ablation that disables ATLAS components one at a time:
\begin{itemize}
  \item \textbf{\texttt{local\_only}}: local fine-tuning without aggregation (no communication).
  \item \textbf{\texttt{standard\_fl}}: standard FedAvg across all clients (no task clustering, no heterogeneous ranks, no split learning, no Laplacian).
  \item \textbf{\texttt{fedavg\_cluster}}: task-aware FedAvg by aggregating only within Phase~1 clusters (no heterogeneous ranks, no split learning, no Laplacian).
  \item \textbf{\texttt{atlas\_no\_laplacian}}: full ATLAS pipeline (task clustering + heterogeneous ranks + split learning) without Laplacian regularization.
  \item \textbf{\texttt{atlas}}: full ATLAS system including Laplacian regularization.
